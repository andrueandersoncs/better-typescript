# Explain semantic findings

Category: enhancement
Status: ready-for-agent
Sources: [GitHub #11](https://github.com/andrueandersoncs/better-typescript/issues/11), [GitHub #12](https://github.com/andrueandersoncs/better-typescript/issues/12)

## Established

Current findings expose `candidateRanges`, `evidenceScope`, and applicability probability. Text distinguishes whole-file context from selected context lines. These are inspection leads, not proven defect locations or explanations.

`Finding` has no rationale field. Final questions return independent applicability and violation Nouls; they do not explain why a policy applies. Actual CLI smoke with a local fixture responder produced whole-file context and probabilities without a rationale.

## Agent Brief

**Category:** enhancement
**Summary:** Explain semantic findings with structured reasons; abstain without concrete breach evidence.

**Current behavior:** Findings expose candidate context and probabilities, but no explanation of the covered operation or suspected breach.

**Desired behavior:** Policies declare named applicability/breach conditions and fixed explanation templates. The existing Noul/Choice evaluator selects supported conditions and source spans; rendering uses those declarations, not generated prose. Reviews describe a suspected breach without asserting certainty. A high score without supported concrete breach evidence becomes `inconclusive` and does not fail the run. A missing suggested fix is not grounds for abstention.

**Key interfaces:**
- `Rule`: declared conditions and their explanation templates.
- `Finding`: supported condition identities, corresponding source context, and rendered reasons.
- `evaluator`: typed judgments connecting the named conditions to the selected evidence set.
- Text/JSON reporting: the same reasons, honest evidence scope, and exit semantics.

**Acceptance criteria:**
- [ ] Every review/violation identifies the covered operation and named breach condition, with supporting source spans and a policy-authored templated reason.
- [ ] Whole-file context remains explicitly whole-file; distant spans can support one relational breach. Candidate ranges are not presented as proven defect locations.
- [ ] A positive score without supported breach evidence becomes `inconclusive`, with an explicit reason and no violation probability. Unsupported findings exit 0; supported reviews exit 0; supported violations exit 1.
- [ ] The current pass/review/violation thresholds and fixed applicability gate remain unchanged.
- [ ] Embedded and project policies share the condition contract. Migrate repository-owned policies, fixtures, and public examples. Missing required declarations produce an actionable policy configuration error, not silent exclusion or a generic fallback.
- [ ] Narrow behavioral coverage exercises unsupported high scores, supported reviews/violations, and a breach requiring distant context. Actual CLI smoke and `./scripts/check.sh` pass; document what live-model quality was actually evaluated.

**Out of scope:** Generated prose, another provider, suggested rewrites, automatic edits, threshold changes, global policy suppression, or deterministic-score guarantees.
