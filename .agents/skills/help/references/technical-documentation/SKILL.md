# Technical Documentation

## Classify the need

Choose the document type from the reader's current need:

| Reader need | Type | Load |
| --- | --- | --- |
| Learn by doing | Tutorial | [Tutorials](references/tutorials.md) |
| Complete a real task | How-to guide | [How-to guides](references/how-to-guides.md) |
| Look up authoritative facts | Reference | [Reference](references/reference.md) |
| Understand a bounded topic | Explanation | [Explanation](references/explanation.md) |

Read the selected reference for its document contract. Use [the Diátaxis workflow](references/how-to-use-diataxis.md) for a mixed documentation set or audit, and [quality guidance](references/quality.md) when the requested judgment goes beyond factual correctness.

## Shared method

1. Name the reader, their immediate need, the promised outcome, and the relevant product or API version.
2. Ground claims in current code, schemas, commands, runtime behavior, specifications, and product decisions.
3. Keep one primary need per document. Move material serving another need into a linked document.
4. Apply the selected document contract and connect likely next needs with useful links.
5. Verify action-oriented docs by following them in a representative environment. Check reference and explanation against their named sources.

For an audit, classify each finding by reader need, cite the conflicting passage, and propose the smallest move, deletion, or rewrite that restores one clear purpose.
