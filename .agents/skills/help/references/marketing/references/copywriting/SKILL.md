# Copywriting

Read the [shared marketing context](../context.md) before work. Reuse supplied and project artifacts; do not create a separate marketing record. Treat verified product facts, customer language, and research provenance as constraints. A proposal is not an implemented fact.

## Establish the page job

Use the request and available evidence to determine:

- **Page and action:** page type, the one action this page should make possible, and the known destination or next step.
- **Visitor intent:** traffic source and what the visitor has already been promised or learned. Match the page's opening and CTA to that context; an ad, search result, referral, and existing-customer visit need not hear the same argument.
- **Reader:** their situation, awareness of the problem and product, language, alternatives, and credible objections.
- **Product truth:** what it does, how it works when material, availability, price or terms when supplied, and only proof that can be traced to supplied or verified evidence.
- **Voice:** preserve wording, terminology, and tone the user supplies. They are the authority on their voice.

Ask only for a missing fact that would change the argument or make the requested action impossible. Do not substitute a made-up trial, guarantee, testimonial, customer, result, integration, price, or comparison for that fact. Omit unsupported proof and briefly list the missing facts outside the finished copy; still deliver complete copy from what is known.

## Build the argument

Choose the shortest page shape that lets a visitor decide. Start with the value relevant to their visit, make the product's path to that value concrete, and address only objections supported by research, product facts, or the request. Connect capabilities to the consequence for this reader without promising an unverified outcome.

A typical full page may need a hero, explanation of the problem or use case, product mechanism or benefits, credible proof, objection answers, and a final action. A small request may need only the requested headline, section, or CTA. Do not force a template, annotations, alternatives, SEO metadata, or a proof section into a request that does not need them.

For every claim, distinguish what the product does from what a customer may achieve. Use named customers, quotations, metrics, availability claims, security claims, pricing terms, or competitor comparisons only when evidence supports the exact statement. If a useful assertion lacks evidence, state the product mechanism plainly or leave it out.

## Deliver

Return usable, finished copy in the requested format, with labels that make page placement clear when a full page is requested. For a page or CTA request, include a primary action with an accurate destination; do not add a CTA to a headline-only request. Keep each section advancing the visitor's decision; do not pad the page with generic persuasion.

After the copy, add a short **Missing facts** note only when omitted proof, a destination, or another material input constrained the draft. Do not leave placeholders inside copy unless the user explicitly asks for a template.

This workflow drafts marketing page copy. For supplied prose that needs a minimal voice-preserving edit, use [deslop](../../../deslop/SKILL.md). For product facts, journey decisions, or durable requirements that need definition, use [product-management](../../../product-management/SKILL.md). For implementation, tracking, experiments, or changes to the site, hand off to the appropriate software work; this workflow does not make those changes.
